Who does what

Each agent is ordinary code with one job. Where an AI model is involved it chooses and phrases; facts come from the systems and the documents.

Stage 1Graph building

Search agent

linkgraph/engine.py · Expansion
  • Searches each target in every police system, in parallel; a phone resolves to a CNIC first.
  • Follows everyone the records name, to the depth and people budget you set; most promising people first.
  • Opens the FIR file of every PSRMS FIR to add complainant, accused, witnesses, IO.
  • With several targets, can stop as soon as they are connected.
~20 logged queries per person

Weak-link analyst

weak_links.py · rarity.py
  • Infers links the systems don't state: same address, same father's name, overlapping hotel stays, shared employer.
  • Discounts common names and crowded addresses; the AI reviews ambiguous addresses.
  • Inferred links are dashed: leads, never facts.
AI optional
Stage 2Evidence team

Collector

evidence/collector.py · sources.py
  • For each FIR: the FIR file report, then its DNA, chemical, FSL and MLO lab reports (PDFs downloaded).
  • For each CRO number: the SAFE dossier PDF with poses and fingerprints.
  • Works in the background; one fetch per document per run, cached; failed APIs are reported, not hidden.
max 40 documents per run

Reader

evidence/readers.py · fir_document.py · pdf_reader.py
  • Reads Urdu FIR pages by label and the text layer of PDFs; scanned pages go to the vision model (the same Qwen model), which reads Urdu and English. No separate OCR.
  • Rule facts first (sections, complainant, accused, witnesses, case position).
  • The AI reads narratives, case diaries and lab findings. Every fact must quote the document word for word; an unquoted claim is discarded.
quote-checked

Linker

readers.link_people
  • Finds the graph's people inside every document by CNIC, phone, vehicle or name.
  • A number found in a FIR file becomes a stated link on the graph, e.g. a witness's phone in a case diary.
hidden links
Stage 3Analysis

Network analyst

linkgraph/network.py
  • Best routes between targets, stated links before inferred, around hub numbers.
  • Clusters, brokers who join them, hidden associates, nearest person with a criminal record.
  • Ranks unsearched people worth the next queries.

Scenario detector

linkgraph/scenarios.py
  • Repeat co-offenders, owner not the driver, possible safe house, SIM fronts, recurring guarantor or witness, insiders.
  • Every finding is tiered: stated, corroborated, inferred or speculative.
Stage 4Investigation

Sherlock, the chat investigator

linkgraph/investigator.py
  • The chat bubble; usable while the graph is still building.
  • Picks tools step by step: routes, findings, person facts, documents, text search, timelines.
  • Can fetch a FIR file, lab reports or a CRO dossier, or check one person in one system; at most 4 live calls per question.
  • Cites every answer; what it fetches joins the case file.
tool looplive tools

Report writer

evidence/case_report.py · report_pdf.py
  • Runs when the graph finishes or you stop it.
  • Writes the summary, assessments, open questions and recommendations; an assessment citing no real evidence is dropped.
  • Renders the PDF: target photos, routes, network diagram, findings, timeline, quoted evidence, pictures, references.
PDF for upper management

How every claim is sourced

The chat and the report cite these ids. Clicking one opens the document at the quoted line.

G#

Graph evidence: a route, a FIR role, a hotel stay or a finding, with the systems that state it.

D#

A document: FIR file, lab report or CRO dossier, with source and time read.

F#

A fact from a document, with the verbatim quote it rests on.

L#

A person of the graph found in a document, and the line that shows it.

One investigation, in order

  1. Targets entered. The portal starts a run; the graph streams to the screen as each system answers.
  2. Search agent expands. Each person is searched; the people their records name are searched next, to the chosen depth.
  3. Evidence team reads alongside. FIR files, lab reports and CRO dossiers are fetched, read into quoted facts, and linked to the graph's people.
  4. You ask Sherlock at any time. It answers from the graph and the case file so far, fetching a document when the answer needs one.
  5. Graph finishes or you stop it. The evidence still being read is finished first, unless you stopped the run.
  6. Report writer drafts the case report. The "Case report" button downloads the PDF; the portal saves the graph with its case file.

Rules every agent follows

No invented evidenceFacts come from systems and documents. A fact without a real quote, or an assessment without real evidence, is dropped.
Leads are marked as leadsInferred and name-only links are shown dashed and called inferred, in the chat and in the report.
Live queries are budgetedEach search, document and chat lookup is a logged police-system query, so each one is capped per run or per question.
